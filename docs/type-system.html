The type system

In Laminar, a call can return one type and leave its argument holding another. To read a signature, follow both the value and the place it came from.

Inference & schemes

Start with ordinary first-order unification. A named top-level function gets a rank-1 scheme, freshly instantiated at each use. Its recursive calls share a monotype while its body is being checked.

fn id(x) x
(id(1), id(true))

The result has type (Number, Bool).

Local bindings are monomorphic. In pure mode, the default, they are also affine. Bind let f = id and the first call to f consumes that local function value. Even two calls at the same type fail. Generalization and permission to reuse a value answer separate questions.

A signature such as id :: (Number) => Number narrows what callers may use. A declared type variable is rigid while checking the definition, so a body that only works on numbers cannot satisfy (a) => a.

Which operations constrain a type variable?
fn label(x) { "${x}" }

In pure mode the scheme prints as (a) => String where Display(a). Each use of label must supply a displayable type, even when the function is passed through another function. Interpolating (1, ("hi", true)) produces (1, ("hi", true)), with quoted strings inside the tuple. A string interpolated directly keeps its original text.

Equality introduces Comparable. In dual mode, copying or sharing a parameter can require Copyable, and leaving it unconsumed on an exit path can require Droppable. Moving a parameter straight to the result requires neither.

What unifies in a data type?

Tuples unify position by position. Lists and vectors each have one element type. Record types are structural and closed: field order is irrelevant, but the field names must match exactly. A TypeScript function accepting {x: number} can receive a variable with extra fields. A Laminar parameter constrained to {x: Number} requires exactly that shape.

Type aliases are transparent. A declared union introduces a nominal type, and matching a constructor constrains both the scrutinee and its payload. Function arity is part of the type: one tuple argument and two separate arguments are distinct.

Reading a flow type

Read A/B in a parameter as “the caller supplies a place holding A, and gets it back holding B.” The arrow still describes the result of the expression. The two outputs can be different.

take :: (a/()) => a
fn take(~x) { x := () }

apply :: ((a) => b, a/b) => ()
fn apply(f, ~x) { x := f(x) }

In apply, reading x gives f its input of type a. The result of type b refills the same place. At the call site, f therefore determines how the caller’s type changes. A Rust &mut T also grants exclusive access, but its referent keeps type T throughout the loan.

~A in an annotation abbreviates A/A. A lens argument comes last and its focus is set up before ordinary arguments are evaluated. A lens can also be the result of a function:

first :: ((a, b)/(c, b)) => a/c
fn first(~(x, y)) ~x

Read the result endpoints from the client’s side. The client sees an a and can put back a c. That changes the first component of the original pair. The repeated b records the untouched sibling.

Moves & swaps

A pure-mode read moves the current value out of its place. The binding survives, ready for another write. A swap evaluates its right-hand side and yields whatever is in the destination at the instant of replacement. If the right-hand side already moved that value, the swap yields unit.

let x = 1let old = x := true(old, x)
Place x
Number · 1
Swap result
—

The binding owns the number 1. A write can exchange it for a value of another type.

Step 1 of 3
An empty place and a place containing () behave differently. Reading an empty place a second time is a use-after-move. A place initialized with unit still has a value to move.

Borrowing & restoration

A persistent alias gives its scope exclusive access to a focus. The owner becomes accessible again at scope exit, with its updated type. Moving from the focus is legal provided the focus is full again when the borrow ends.

{
    let p = (1, "north")
    {
        let (x, y) = ~p
        x := true
    }
    p
}

The final pair has type (Bool, String). The two component aliases can be used independently. Accessing p while they are live fails. Reborrowing ~x suspends access through x until the inner borrow ends. Supplying the same place twice in a tuple lens would create overlapping writers.

Computed focuses and cleanup
fn shifted(~x) ~{
    lens v <- x + 2
    x := v - 2
}

Starting with x = 1, setup moves the number out and lends the client a temporary holding 3. If the client writes 5, restoration binds v to that final value and writes 3 into the original place. Storage used by cleanup stays protected until restoration finishes. A raw lens into an owned local cannot escape its backing.

Constructor fields and vector elements

In a borrowed match, field bindings focus parts of the selected constructor. The same constructor must be reconstructed with every moved field refilled. A lens assembled as Some(x) can expose a payload while fixing the tag. Its printed /= marks the restriction on replacing the whole constructor.

An index focus keeps a homogeneous vector intact. For an owned vector v, use dup(~v[i]) to copy an element or v[i] := replacement to swap it. The replacement must have the element type. A free-standing v[i] cannot move a hole out of the vector.

Branch joins

At a match, unifying the arm results is only the first check. The checker must also reconcile the state each arm leaves for the continuation.

fn choose(flag) {
    let x = 1
    match flag {
        true  -> { x := true
                   () }
        false -> ()
    }
    x
}

Both arms produce unit. Yet the true arm leaves x holding a Bool and the false arm leaves a Number. The checker reports branch-state. Writing false to x in the other arm, then yielding unit there too, makes the post-match type Bool.

Availability has its own join rule. If one arm moves a value out, the continuation cannot assume the place is full. Refill it on every path before reading again. A borrowed place must also be restored on every path that ends its loan.

Dual mode

A file with // laminar: dual on its first nonblank line opts into shared immutable bindings alongside exclusive ones. Lens endpoints still work the same way. What changes is which bindings allow another read, a move, or a borrow.

BindingReading itTaking a lens
Pure let xMoves the valueAllowed
Dual let xShares an immutable valueRejected
Dual let mut xMoves the valueAllowed
// laminar: dual
{
    let p = (1, 2)
    let mut q = dup(p)
    fst(~q) := true
    (p, q)
}

The result is ((1, 2), (true, 2)). dup(p) gives the shared pair an independent, owned copy. For an exclusive binding use dup(~q) to copy its contents while keeping it full. Going the other direction, let p = q moves a shareable value out of exclusive storage and freezes it.

When dropping a value is an error

mut describes access to storage. linear describes an obligation attached to a type. A mut Number may go unused. A value of a declared linear type must be consumed on each path and cannot be duplicated or frozen into a plain binding.

type linear Conn {
    Conn(Number)
}
fn finish(mut c) {
    match c { Conn(fd) -> fd }
}

An owned match consumes the wrapper. A borrowed match can inspect its fields, leaving the obligation with its owner. Returning a linear value or handing it to a consuming function transfers that obligation.

Closures and owned lenses

Capturing an exclusive value moves it when the closure is created. An ordinary closure cannot borrow an outer local because the call may happen after the local’s scope ends. Capturing a borrowed focus’s contents is a move and the original focus still needs refilling.

Dual mode also supports owned lenses. A lens-returning producer with no borrowed lens parameter can supply a focus with its own cleanup. Passing it to ~x reborrows it. Passing it to mut ~x transfers the focus and its restoration obligation. The call-site spelling is ~place in both cases. A closure that captures an owned lens or linear value is itself linear and must be consumed.
